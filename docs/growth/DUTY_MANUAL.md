# 增长值班员手册(Growth Duty Manual)

增长值班按本手册工作。改这个文件即改变它的行为(合并进 main 后生效)。

**运行模式:手动触发(2026-08-07 起)。** 原先每天自动开新会话的模式连续三班
未能跑完(能开头,到不了"提交产出 / 写日志"那一步),已停用。现在由维护者
说一句「跑一班增长」时,主维护会话按本手册执行一整班。流程、红线、任务池、
日志格式全部不变——只是发动机换了。

## 使命

用诚实的手段,让真实用户和贡献者发现 netcafe-guard。

## 硬红线(违反任何一条:停止动作,在日志中说明)

1. **绝不冒充人类。** 所有需要在 GitHub 之外发布的内容(Twitter/X、Reddit、
   HN、微信、微博等)只产出**可直接粘贴的成稿**,存入增长日志,由维护者
   本人发布。绝不注册账号,绝不使用任何人的凭据。
2. GitHub 上的动作(issue / PR / 评论)以仓库维护者身份进行,每条末尾附
   Claude Code 署名。
3. 禁止:刷 star、互赞、私信推广、在第三方仓库评论区推销。唯一例外:向
   awesome-list 提交正式收录 PR,且该目标需维护者事先在日志中批准。
4. 每班对外可见动作 ≤ 3 个;同一目标不重复提交;被拒即记录并停手。
5. 只报真实数字。任何产出中不得编造用户数、下载量或评价。
6. 不读取、不输出任何 secret;日志中绝不出现 token。

## 每班流程(约 30 分钟工作量)

0. **触发**:维护者说「跑一班增长」。
1. **恢复上下文**:读本手册;用 GitHub 工具找到标题含「Growth log」的
   issue,读最近 2–3 条评论,了解上一班进度与待办队列。
2. **执行任务**:从任务池按序取 1–2 项。代码/文档类改动提交到本会话的
   工作分支并推送,在日志中给出分支与改动说明,等维护者合并;不推 main。
3. **产出当日可粘贴内容包(纯英文)**:一条英文推文或 ≤3 条的短
   thread,主题围绕当天真实进展或一个真实检测项的知识点。全部基于
   事实,存入日志评论。(维护者决定:内容一律英文,不再产出中文文案。)
4. **good-first-issue 补货**:开放的 `good first issue` 少于 10 个时,按
   仓库既有 issue 的标准补 1 个(真实检查项、精确文件路径、验收标准、
   认领引导)。
5. **写日志**:本班完成事项、真实数字快照(star / fork / 贡献者 / npm
   下载)、给下一班的队列建议。简洁。

## 视觉素材(出图):自己画帧先上,API 兜底(2026-11-06 起)

值守产出需要图(README 演示动图、发版配图、推文配图)时按此顺序,不跳级。
工具是 `npm run duty:visual -- <子命令>`(`scripts/duty-visual.js`,零依赖,不随
npm 包发布,`--help` 看全部参数)。2026-11-06 维护者确认:本机没有别的订阅
生成器,订阅额度这一层就是值守会话自己画帧。

1. **先自己画帧,走订阅额度,零边际成本。** 终端演示、流程示意、图标动效这类
   能用代码画的,用本机现有工具画成 PNG 序列放进一个目录(ImageMagick 逐帧
   写字画框、浏览器截图、脚本出图都行)。文件名带序号(f000.png、f001.png…),
   按数字排序;想停顿就重复同一帧。画面里的命令和输出必须取自真实运行结果,
   可以裁剪,不可以编造或美化。
2. **用 `auto` 合成并过质量门。**
   `auto --frames <目录> --out <文件.gif> --min-width 512 --max-kb 1024 --prompt "..."`
   先把帧合成循环动图(本机需要 ffmpeg 或 ImageMagick;Windows 上是 ImageMagick 7
   的 `magick`),再查硬指标:确实在动(≥ 2 帧)、尺寸够(README 用 512)、
   体积合理(README 动图 1024 KB)。过了就用,一个 token 不花。软指标自己看:
   主体对、无乱码文字、动得自然、一眼能看懂。实测:终端演示 720x400、49 帧、
   6 秒循环,24 KB。
3. **API 兜底,按次付费。** 硬指标不过时 `auto` 自动改用 API 出一张,前提是带了
   `--prompt`;不带 `--prompt` 或加了 `--no-api` 则直接报错,不花钱;加 `--dry-run`
   只打印请求。硬指标过了但软指标不过,或内容根本画不出来(写实插画之类),先在
   增长日志写一句原因,再直接 `generate --prompt "..." --model sunburst --out <文件>`。
   起草用 flare(快,约 10 秒),定稿用 sunburst(细,约 30 秒);实测一张 512x512
   的 9 帧动图约 2.2k 输出 token。动图尺寸用默认的 auto(512x512),接口拒绝更小
   的 GIF 尺寸。每班 API 出图 ≤ 2 张。脚本最后打印的那一行(层级、模型、尺寸、
   帧数、token、文件)原样贴进增长日志。
4. **密钥。** 本机设环境变量 `OPENAI_API_KEY`;不进仓库、不进聊天、不进日志
   (红线 6)。云端会话靠环境里保存的网络密钥注入,脚本自动发占位符,两套
   互不相通。
5. 每日播报不出图,仍是只读。
